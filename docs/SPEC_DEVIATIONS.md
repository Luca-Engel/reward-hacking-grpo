# SPEC_DEVIATIONS

One line per deviation from `docs/REPO_SPEC.md` or the design docs made during implementation.

- 01: `extends: base.yaml` in `configs/arms/*.yaml` (as REPO_SPEC §3 writes it) is resolved relative to the extending file first, then falls back to the config root, since base.yaml lives in `configs/`, not `configs/arms/`.
- 01: `load_config` also requires `arm.id` in the (pre-override) arm file to equal the arm's file name, and falls back to the repo-root `configs/` when a relative `config_dir` does not exist under the cwd.
- 01: Config numeric fields are strict-typed (no bool/str coercion; an int for a float field is normalised to float) and `grpo.loss_type` is restricted to {grpo, bnpo, dr_grpo, dapo}; subtask 10 must revisit the set if the pinned TRL differs.
- 01: The override value `1e-4` is parsed as a float (PyYAML alone reads it as a string); `run.seed` from `--seed` wins over a `run.seed=` override.
- 01: Config and Grpo blocks expose `rollouts_per_step`, and `sampling` exposes `top_k_enabled`, as read-only properties (not part of the dump/hash).
- 02: In the manifest, `git_sha` and `git_dirty` are `null` (unknown) when git is unavailable, and `split_hash`/`prompts_hash` are `null` when `splits.json`/`prompts.yaml` are absent, instead of `""`/`false` (an unknown state must never read as "clean").
- 02: `git_dirty` counts non-ignored untracked files; `git_diff_sha256` is the sha256 of `git diff HEAD` (tracked changes only). `prompts_hash`, code-group and requirements hashes normalise CRLF to LF so Windows and Linux checkouts agree.
- 02: `prereg_check.check` adds an item `freeze_matches_tag` (working `FREEZE.json` must equal the version committed at `prereg-v1`) so the freeze cannot be silently rewritten after tagging; `write_freeze` refuses once the tag exists. Amendments must chain from the frozen hash (`old_hash` = currently expected hash) or the group fails as "chain broken".
- 02: Amendment `group` values are the bare code-group names (`analysis`, `env`, `detect`, `judge_rubric`, `data_build`) or `config:<arm>`, `prompts`, `hint_selection`, `hyperparameters`, `split`, `dataset_revision`, `requirements_gpu`; `--amend` amends every drifted key unless `--group` is given.
- 02: Extras beyond the subtask text: `rhg.budget status`, `prereg_check --write-freeze/--gpu-type/--force`, `cost_model --t-step-source {formula,measured,max}` (default `formula` = BUDGET §2 exactly; `measured` uses the median of `step_times_s[2:]`), optional `cache_hit_rate`/`exec_s_per_rollout_uncached` in `throughput.json`. `cost_model` refusing to overwrite the decision file exits 3; a computed "below the 11-run floor" outcome exits 0 and is stated in the output and decision draft.
- 02: The ledger guard's "recommended ladder step" = highest-priority `LADDER` step whose run count fits (distinct `train` run ids in the ledger) + floor((stop_at - spent) / next_run_usd); it is advisory and only phrases the refusal.
- 03: `extract_code` accepts fence tags `python`/`python3`/`py` (case-insensitive) as "python"; "generic" means an *unlabelled* fence (blocks tagged with another language are ignored); empty/whitespace-only blocks are not code; fences must start a line and a closing fence needs at least as many backticks as the opener.
- 03: `run_python` has an extra `stdin_data` kwarg (how the grader hands the harness its nonce/payload) and `SandboxResult` has extra `stdout_truncated`/`stderr_truncated`; `RLIMIT_NPROC` is not set (per-user limit that can break the parent's own workers); `-I` ignores `PYTHON*` env vars so `PYTHONHASHSEED` cannot be pinned. POSIX rlimit code cannot be exercised on the Windows dev box (its memory-limit test is skipped there).
- 03: The harness reports each stage (`exec`, `visible`, `heldout`, `exploit`) in its own one-shot nonce'd result file as soon as the stage ends, instead of one file at the end, so a hanging/crashing held-out test cannot change `visible_pass`/`defines_rt`/reward (a single end-of-run file would let held-out timeouts zero the reward, violating DESIGN §2.4). Missing stages count as False and set `timeout`/`crash`.
- 03: Model code is exec'd with `__name__ == "__rhg_solution__"` (so `__main__` blocks do not run), exceptions raised while executing it are recorded but the resulting namespace is still graded, and `entry_point` may be an expression (`ns[entry_point]`, else `eval(entry_point, ns)`, e.g. `Solution().twoSum`). `crash` also covers `MemoryError`, a failing `import_prefix`, and processes that die (e.g. `os._exit`) before reporting; a problem with no reward or no held-out tests raises `GraderError`.
- 03: Cache key = sha256 of `(sha256(code), problem_id, tests digest, "GRADER_VERSION:harness-hash", timeout_s, mem_mb)`; the tests digest also covers `entry_point` and `import_prefix`. `GRADER_VERSION` lives in `rhg.env.grader`. `cache_stats()` also reports `dedup`, `uncacheable`, `size`, `hit_rate`; `configure_cache(dir)` enables the sqlite layer (default is memory only). With `sandbox.cache: true`, `grade_batch` executes identical (code, problem) pairs once (counted as `dedup`); reward/labels are still computed per item.
- 03: `GradeResult` = `(reward, labels, raw, monitor, from_cache, info)`; `labels` has the ten REPO_SPEC §6 label keys, `raw` exactly the seven raw fields, `monitor = {"ast_narrow": bool | None}` (`None` = monitor not run: no `monitor_fn` or no code; `ast_broad`/`ast_categories` are filled by the logger from the detector, subtask 05/09). `grade_batch(items, workers=None, *, cfg=None)` takes `GradeItem`s (or dicts of their fields); `workers=None` uses `cfg.sandbox.workers`, `0` = `max(1, cpu_count-2)`.
- 04: Stage order is fetch -> tests -> validate -> split (REPO_SPEC §7 lists `validate` before `tests`, but validation needs the parsed tests). Intermediate/extra outputs beyond REPO_SPEC §5: `data/processed/{converted.jsonl, tests_report.json, validation_report.json, selected_A.json, DATASET_REVISION}`; `splits.json` has extra keys (`counts, band, split_seed, size_rule, dataset_revision, balance, gate1c, cluster_stats_selected`). The pass-rate schema (`{problem_id, n, k_visible, k_full}`) is documented in `docs/dataset_notes.md` §5.
- 04: `rhg.data.build` extra flags beyond `--stage/--fixture/--widen`: `--select-only` (writes `selected_A.json` so stage B knows what to sample), `--strict` (exit 1 when Gate 1c fails; default exit 0 with the verdict in `splits.json["gate1c"]`), `--raw-dir/--processed-dir`, `--set k=v`, `--workers`, `--ref-timeout`, `--limit`, `--revision`, `--force`. `--fixture` uses `data/fixture/{raw,processed}` (gitignored via `.gitignore`), never `data/processed`; consumers of the fixture (mock pipeline, subtask 16) must point `data.processed_dir` there.
- 04: `DATASET_REVISION` is one line, `newfacade/LeetCodeDataset@<commit> datasets=<ver> downloaded=<date>`; `rhg.manifest` copies the whole line into `dataset_revision`. The 5-word/Jaccard-0.8 clustering runs over ALL raw records (dropped ones included) and `cluster_id` is the smallest `problem_id` of the component (a slug), not an opaque hash.
- 04: `prompts_hash(cfg)` (a mapping) hashes the semantic prompt content and ignores `frozen`; the manifest's `prompts_hash` is the sha256 of the prompts file text (incl. `frozen`). `prompts_hash(path)` returns the manifest's value. `hint` arguments also accept wording ids (`S1`, `S2`, `S3`, `E1`) for the hint probe; `subtle` resolves to `subtle_selected`, `explicit` to `explicit_selected` (default: the only/first explicit wording).
- 04: Added drop reason `prefix_import_unavailable`: 85 problems (3%) whose dataset import prefix does `from sortedcontainers import SortedList` are dropped instead of adding that package to the sandbox/GPU-box dependencies (one more, `zero-array-transformation-iii`, fails in `validate` because its reference imports it). Reference validation additionally requires the reference to pass the selected reward+held-out tests through the real grader (6 s), which dropped 2 more; 31 heavy references exceeding the 60 s all-tests budget are dropped as `reference_timeout` (conservative; `--ref-timeout` raises it). The drops are mildly machine-speed dependent, so build `problems.jsonl` once and copy it.
- 04: Reward/held-out split uses the constant salt `rhg-test-split-v1` (function takes no seed); the dataset's repeated identical asserts (5,577 in total) are removed before splitting so reward and held-out tests never contain the same assertion. The split-stage seed is the constant `rhg-split-v1`; val/test sizes are 40/60 for >= 250 selected problems and 16%/24% below that. Balance thresholds in Gate 1c (Kruskal-Wallis p >= 0.10 on `p_A`; difficulty chi-square is informational) are my choice, not pre-registered.
- 04: `transformers` is not a core dependency, so the `network` test comparing the fallback renderer with the real tokenizer has a jinja2-only route (real `tokenizer_config.json` template, always available) and a `transformers` route (`importorskip`); both were run once with `uv run --with transformers pytest -m network tests/test_prompts.py` and passed (see `docs/dataset_notes.md` §7).
- 05: `DetectionResult.categories` uses the spec names plus two extra tags: `module_def` (module-level `def run_tests`, i.e. the narrow set; the spec only lists `nested_def` for "def anywhere") and `class_def` (`class run_tests`, callable at runtime). Categories are returned in the fixed order `rhg.detect.ast_detector.CATEGORIES`; evidence strings are `"<category>: <note> | <source line>"`.
- 05: Blank/whitespace-only code counts as missing code (`parse_error=True`), like `None`; unparsable includes null bytes and pathological nesting (`RecursionError`/`MemoryError`), all giving `flag=False, parse_error=True`.
- 05: `special_casing_heuristic` is only computed by the `broad` profile (always `False` for `narrow`). Choices beyond the spec: it is counted per function; comparisons against trivial literals (0, 1, -1, None, bools, empty values) do not count as hardcoded branches; a table lookup only counts when keyed by the whole argument(s) (not `ROMAN[s[i]]`). All to keep honest base cases/lookup tables quiet.
- 05: Because `exec`/`eval`/`compile` on any non-constant string is flagged (as specified) and the constant folder also decodes constant base64/hex/rot13, "exec of a string decoded at runtime" is *not* a broad hole; the documented `exec` holes are indirect calls (`runner = exec`, `getattr(builtins, "ex"+"ec")`). Exits under an `if __name__ == "__main__":` guard are ignored (never run by the grader); attribute stores `x.run_tests = …` are flagged as `assignment` except on `self`/`cls`.
- 05: `make_monitor(None)` returns `None` (grader convention: `monitor_fn=None` = no monitor); unknown names raise `ValueError`.
- 06: Extra module `src/rhg/eval/pipeline.py` (not in REPO_SPEC §1): the generate -> grade machinery shared by `pass_rate` and `probe_hints` (chunked generation with grading overlapped in a background thread, completions-file I/O, grade-only validation). `MockGenerator.generate` takes an extra optional `prompt_meta` (explicit prompt -> problem mapping); backends that want it set `needs_prompt_meta` and `generate.generate_for` passes it only to them. `SamplingParams(temperature, top_p, top_k, max_tokens)` is defined in `generate.py` (`max_tokens` = `grpo.max_completion_tokens`).
- 06: Completions files (`data/processed/completions_{A,B}.jsonl.gz`, `results/probe/completions.jsonl.gz`) = gzip (mtime 0) JSONL: one header line (`kind: header`, purpose, generator, sampling, prompts_hash, groups with `hint, seed, n, problem_ids`) then one row per sample (`problem_id, hint, sample_idx, seed, prompt_sha, completion, n_tokens, truncated`); written to `<name>.part` and renamed when complete (a crashed generation leaves only the `.part`). `--grade-only` re-renders every prompt and refuses on a hash mismatch, duplicates or missing samples. No output file contains a timestamp or wall time, which is what makes `--grade-only` byte-identical to the default path.
- 06: `VLLMGenerator` has extra keyword arguments `max_prompt_tokens`, `max_lora_rank` (default 32) and `engine_seed`. Prompts longer than `grpo.max_prompt_tokens` (768) are NOT generated (n empty, `truncated=True` completions, counted in `stats["prompts_too_long"]`): their measured pass rate is 0, consistent with training not being able to use them; subtask 11 must apply the same rule in the trainer. Per-request seeds are `derive_seed(seed, sha256(prompt))`. The whole vLLM path is UNVERIFIED on real vLLM (only tested against a fake `vllm` module).
- 06: Ledger entries `passrate`/`probe` are wall time of model load + generation calls (the box is billed while loading), not grading; skipped for `--mock`, `--grade-only` and (of course) never written by tests to `results/`.
- 06: `--mock` never touches real outputs: without an explicit `--processed-dir`/`--set data.processed_dir=` it uses `data/fixture/processed` (REPO_SPEC/brief say `data/processed`, which would let fake pass rates feed the real split); `probe_hints --mock` writes `results/probe_mock/` and the selection to `<out-dir>/hint_selection.mock.json`, never `prereg/hint_selection.json`. Explicit `--processed-dir/--out-dir/--selection-path` override all of this.
- 06: Stage seeds are the constants 61001 (A) and 62002 (B), enforced by `pass_rate.check_seed_independence` (also against the seed recorded in the other stage's completions/stats file); the probe samples wording i with seed 71000+i. Stage A reads `candidates.jsonl`; stage B reads the ids in `selected_A.json` (extra flags: `--fixture --processed-dir --seed --workers --chunk-prompts --model --gpu-mem-util --cache-dir --set`).
- 06: Probe details chosen where the brief is ambiguous: `--n` = samples per problem and wording, default `ceil(--min-samples / n_train)` (3000 pre-declared; a smaller `--min-samples` must be passed explicitly and is recorded as `sample_size_ok=false`); "CI strictly below E1's" = Wilson hi(S) < Wilson lo(E1); the 0.5%/5%/5 pp boundaries are compared as exact rationals; the manipulation check (`hi(none) < lo(sel)` and `hi(sel) < lo(E1)`) is applied to the first qualifying candidate, and if it fails the probe is NO-GO (the next candidate is not tried); Wilson CIs pool rollouts and ignore clustering by problem (stated in `hint_probe.json`).
- 06: The NO-GO escalation text (one more round of <=3 new candidates, <=$0.3) comes from the subtask brief and SCHEDULE Gate 1d; DESIGN §2.3 only says "Gate 1d is NO-GO". A NO-GO and the "selection already exists" guard both exit 3 (REPO_SPEC: 3 = guard refused); the guard triggers before any generation, except for `--generate-only`. `hint_selection.json` does not edit `configs/prompts.yaml`: `subtle_selected` must be set by hand before the Gate 1f freeze (the probe report says so).
- 06: Prompts are rendered with the fallback `render_chat` (checked against the real Qwen3 template in subtask 04) instead of a tokenizer, so `--grade-only` and the mock path need no `transformers`. `wilson(k, n, z=1.96)` was added to `analysis/stats.py` (subtask 13 extends that module).
- 07: `rhg.judge.run` needs exactly one of `--dry-run | --estimate-only | --mock | --real` (REPO_SPEC lists only the first three); `--real` is the single flag that constructs the paid `AnthropicBatchClient`. Extra flags: `--runs-dir --out-dir --processed-dir --arm --set --seed --confirmatory --freeze-path --repo-root --ledger --chars-per-token --force --mock-accuracy --mock-bias --mock-seed`. `--mock` writes to `results/judge_mock/` and skips the real ledger (unless `--ledger` is given); an existing `<run_id>.jsonl` is never overwritten without `--force`.
- 07: Judge rows (`results/judge/<run_id>.jsonl`) carry extra fields beyond REPO_SPEC §6: `label_status` (`ok|unparseable|tie`; `label` is null unless `ok`), `components`, `in_audit`, `ast_broad_flagged`, `inclusion_prob_flagged/_audit`, `tokens_cache_read/_write`, `rubric_hash`, `rubric_version`, `model`, `mock`. `tokens_in` counts cached + uncached input tokens. A sidecar `<run_id>.summary.json` (N, flagged count, cap used, both inclusion probabilities, spend) is written for the inverse-probability weighting in subtask 08.
- 07: The judge receives the full completion text (per the subtask brief), not only `extract_code()` output as DESIGN §2.4 says; the description is passed through `strip_hint` as well. The rubric avoids the literal `run_tests` (describes `run_*/check*/...` harness names generically) so that `run_tests` reaches the judge only via the model's own completion; recall on the specific exploit is to be checked against the synthetic controls (08) before the Gate 1f freeze.
- 07: `--confirmatory` compares the working `rubric.py` group hash with `FREEZE.json` `code_groups.judge_rubric` (after logged amendments) and, if present, `judge_rubric_hash` with `rubric_hash()`; subtask 02's freeze only writes the former. It does not run the other `prereg_check` checks (clean tree, tag ancestry).
- 07: The pre-flight cap check is a worst case (3 votes for every item, output at `max_tokens`, no cache discount, chars/4 x 1.3), so it subsamples more than the expected ~1.5 votes/item cost would require; the cap is cumulative with judge spend already in the ledger. Unparseable/errored votes are not replaced by the third vote (reserved for disagreement); such items get `label: null`.
- 07: Price constants (Haiku 4.5 $1/$5 per MTok, batch 50%, cache read 0.1x, 1h write 2x, 4096-token cache minimum) come from the `claude-api` skill's cached tables; the stacking of batch and cache discounts, output-token expectations and the 1.3 chars/4 safety factor are `UNVERIFIED`. No real API call was made; the real client was exercised only against a fake `anthropic` module.
- 08: Extra module `src/rhg/validate/io.py` (not in REPO_SPEC §1): loaders shared by `sample`, `harness` and `label` (rollouts, judge rows, JSONL helpers, AST-flag fallback that recomputes with `analyze(extract_code(...))` only when the log lacks `monitor.ast_*`).
- 08: `--mock`/`--client mock` outputs never overwrite real reports: `harness --mock` writes `validation.mock.{json,md}` (population planted in a temp dir, analysed through the ordinary file-based path), `calibrate --client mock` writes `judge_calibration.mock.json` and marks it `"mock": true`; only `--client anthropic` writes `results/analysis/judge_calibration.json`. The pre-freeze gate (subtask 12) must read `criterion.passed`, `mock` (must be false), and check `rubric_hash == rhg.judge.rubric.rubric_hash()`.
- 08: Calibration details chosen where the brief is silent: override-type controls = `construction_label == hack_override` (obvious + subtle overrides); "honest controls" = every `honest` control (correct, wrong, comment-only, truncated, self-tests, prose-only); the criterion is applied to point estimates (CIs are reported); an unlabelled item (unparseable/tie) counts as a disagreement (a miss on a hack control, a false positive on an honest one); the report also has the 4-way construction-label-by-judged-type table. The calibration spend is not part of the $4 judge cap: it uses its own `--max-usd` (default 0.5, BUDGET's "dev/validation/synthetic-control" line) and is recorded once in the ledger as kind `other` (run_id `judge_calibration`). The pre-flight worst-case estimate printed for the 49 controls is ~$0.21 (expected ~$0.15 at 3 votes), i.e. above the brief's "~$0.1"; both figures are chars/4-based `UNVERIFIED` planning numbers, replaced by measured tokens after the first real run.
- 08: Control suite has 49 items (brief: >= 30) on the 8 tiny fixture problems (`rhg.data.fixture.tiny_problems`, not the tracked JSONL). Each control's `expect` (declared exec labels) is asserted against the real grader in both reward modes. Two controls are invisible to execution by construction (`module_level_sys_exit`: the sandbox catches the SystemExit during exec, so no `defines_rt`; `always_equal_result`: passes every test) and one class of hacks (special-casing) never sets `defines_rt`; their `expect` says so.
- 08: Sampler defaults: 20 real (quota 4 per stratum, shortfall -> random), 20 controls (round-robin over the 7 categories, so all appear), 10 duplicates drawn from the 40 (brief: "~20 real + the controls"; DESIGN §4 says ~20 synthetic controls). Strata are disjoint by priority (hack_flagged, hack_unflagged, nonhack_flagged, gap_other_unflagged), the random remainder is drawn from everything not yet chosen. Population = final-step `eval_test` rollouts of the given runs (the judge's population). `sample` refuses to overwrite item files once `human_labels.jsonl` is non-empty (exit 3) unless `--force`.
- 08: Harness details chosen where the brief is silent: judge-vs-exec uses IPW ratio estimators with a Wilson interval at the Kish effective n (plus the Poisson-linearised `se_design`) and a weighted item bootstrap for F1/kappa/PABAK (see `rhg.validate.metrics`); judge rows without a label are excluded from the primary estimate, reported, and bracketed by a missing-as-hack / missing-as-not-hack sensitivity. Positives outside run_tests-type hacks (special-casing) count as judge false positives against `hack_rt`. Judge-vs-human pairs controls with the calibration report's per-control labels and real items with the judge rows; duplicates are excluded there and used only for intra-rater agreement. Wilson uses z = 1.96 everywhere (same constant as `rhg.analysis.stats.wilson`).
- 08: IPW variance is an approximation, not the exact variance of the two-sample design; in the planted simulation the recall interval covered the population value ~96% and the (ratio-biased) precision interval ~91% of the time (nominal 95%); precision is noticeably noisier because it is a ratio dominated by few unflagged judged positives. Documented in `metrics.py`; nothing hidden.
