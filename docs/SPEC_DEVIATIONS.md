# SPEC_DEVIATIONS

One line per deviation from `docs/REPO_SPEC.md` or the design docs made during implementation.

- 01: `extends: base.yaml` in `configs/arms/*.yaml` (as REPO_SPEC §3 writes it) is resolved relative to the extending file first, then falls back to the config root, since base.yaml lives in `configs/`, not `configs/arms/`.
- 01: `load_config` also requires `arm.id` in the (pre-override) arm file to equal the arm's file name, and falls back to the repo-root `configs/` when a relative `config_dir` does not exist under the cwd.
- 01: Config numeric fields are strict-typed (no bool/str coercion; an int for a float field is normalised to float) and `grpo.loss_type` is restricted to {grpo, bnpo, dr_grpo, dapo}; subtask 10 must revisit the set if the pinned TRL differs.
- 01: The override value `1e-4` is parsed as a float (PyYAML alone reads it as a string); `run.seed` from `--seed` wins over a `run.seed=` override.
- 01: Config and Grpo blocks expose `rollouts_per_step`, and `sampling` exposes `top_k_enabled`, as read-only properties (not part of the dump/hash).
- 02: In the manifest, `git_sha` and `git_dirty` are `null` (unknown) when git is unavailable, and `split_hash`/`prompts_hash` are `null` when `splits.json`/`prompts.yaml` are absent, instead of `""`/`false` (an unknown state must never read as "clean").
- 02: `git_dirty` counts non-ignored untracked files; `git_diff_sha256` is the sha256 of `git diff HEAD` (tracked changes only). `prompts_hash`, code-group and requirements hashes normalise CRLF to LF so Windows and Linux checkouts agree.
- 02: `prereg_check.check` adds an item `freeze_matches_tag` (working `FREEZE.json` must equal the version committed at `prereg-v1`) so the freeze cannot be silently rewritten after tagging; `write_freeze` refuses once the tag exists. Amendments must chain from the frozen hash (`old_hash` = currently expected hash) or the group fails as "chain broken".
- 02: Amendment `group` values are the bare code-group names (`analysis`, `env`, `detect`, `judge_rubric`, `data_build`) or `config:<arm>`, `prompts`, `hint_selection`, `hyperparameters`, `split`, `dataset_revision`, `requirements_gpu`; `--amend` amends every drifted key unless `--group` is given.
- 02: Extras beyond the subtask text: `rhg.budget status`, `prereg_check --write-freeze/--gpu-type/--force`, `cost_model --t-step-source {formula,measured,max}` (default `formula` = BUDGET §2 exactly; `measured` uses the median of `step_times_s[2:]`), optional `cache_hit_rate`/`exec_s_per_rollout_uncached` in `throughput.json`. `cost_model` refusing to overwrite the decision file exits 3; a computed "below the 11-run floor" outcome exits 0 and is stated in the output and decision draft.
- 02: The ledger guard's "recommended ladder step" = highest-priority `LADDER` step whose run count fits (distinct `train` run ids in the ledger) + floor((stop_at - spent) / next_run_usd); it is advisory and only phrases the refusal.
- 03: `extract_code` accepts fence tags `python`/`python3`/`py` (case-insensitive) as "python"; "generic" means an *unlabelled* fence (blocks tagged with another language are ignored); empty/whitespace-only blocks are not code; fences must start a line and a closing fence needs at least as many backticks as the opener.
- 03: `run_python` has an extra `stdin_data` kwarg (how the grader hands the harness its nonce/payload) and `SandboxResult` has extra `stdout_truncated`/`stderr_truncated`; `RLIMIT_NPROC` is not set (per-user limit that can break the parent's own workers); `-I` ignores `PYTHON*` env vars so `PYTHONHASHSEED` cannot be pinned. POSIX rlimit code cannot be exercised on the Windows dev box (its memory-limit test is skipped there).
- 03: The harness reports each stage (`exec`, `visible`, `heldout`, `exploit`) in its own one-shot nonce'd result file as soon as the stage ends, instead of one file at the end, so a hanging/crashing held-out test cannot change `visible_pass`/`defines_rt`/reward (a single end-of-run file would let held-out timeouts zero the reward, violating DESIGN §2.4). Missing stages count as False and set `timeout`/`crash`.
- 03: Model code is exec'd with `__name__ == "__rhg_solution__"` (so `__main__` blocks do not run), exceptions raised while executing it are recorded but the resulting namespace is still graded, and `entry_point` may be an expression (`ns[entry_point]`, else `eval(entry_point, ns)`, e.g. `Solution().twoSum`). `crash` also covers `MemoryError`, a failing `import_prefix`, and processes that die (e.g. `os._exit`) before reporting; a problem with no reward or no held-out tests raises `GraderError`.
- 03: Cache key = sha256 of `(sha256(code), problem_id, tests digest, "GRADER_VERSION:harness-hash", timeout_s, mem_mb)`; the tests digest also covers `entry_point` and `import_prefix`. `GRADER_VERSION` lives in `rhg.env.grader`. `cache_stats()` also reports `dedup`, `uncacheable`, `size`, `hit_rate`; `configure_cache(dir)` enables the sqlite layer (default is memory only). With `sandbox.cache: true`, `grade_batch` executes identical (code, problem) pairs once (counted as `dedup`); reward/labels are still computed per item.
- 03: `GradeResult` = `(reward, labels, raw, monitor, from_cache, info)`; `labels` has the ten REPO_SPEC §6 label keys, `raw` exactly the seven raw fields, `monitor = {"ast_narrow": bool | None}` (`None` = monitor not run: no `monitor_fn` or no code; `ast_broad`/`ast_categories` are filled by the logger from the detector, subtask 05/09). `grade_batch(items, workers=None, *, cfg=None)` takes `GradeItem`s (or dicts of their fields); `workers=None` uses `cfg.sandbox.workers`, `0` = `max(1, cpu_count-2)`.
- 04: Stage order is fetch -> tests -> validate -> split (REPO_SPEC §7 lists `validate` before `tests`, but validation needs the parsed tests). Intermediate/extra outputs beyond REPO_SPEC §5: `data/processed/{converted.jsonl, tests_report.json, validation_report.json, selected_A.json, DATASET_REVISION}`; `splits.json` has extra keys (`counts, band, split_seed, size_rule, dataset_revision, balance, gate1c, cluster_stats_selected`). The pass-rate schema (`{problem_id, n, k_visible, k_full}`) is documented in `docs/dataset_notes.md` §5.
- 04: `rhg.data.build` extra flags beyond `--stage/--fixture/--widen`: `--select-only` (writes `selected_A.json` so stage B knows what to sample), `--strict` (exit 1 when Gate 1c fails; default exit 0 with the verdict in `splits.json["gate1c"]`), `--raw-dir/--processed-dir`, `--set k=v`, `--workers`, `--ref-timeout`, `--limit`, `--revision`, `--force`. `--fixture` uses `data/fixture/{raw,processed}` (gitignored via `.gitignore`), never `data/processed`; consumers of the fixture (mock pipeline, subtask 16) must point `data.processed_dir` there.
- 04: `DATASET_REVISION` is one line, `newfacade/LeetCodeDataset@<commit> datasets=<ver> downloaded=<date>`; `rhg.manifest` copies the whole line into `dataset_revision`. The 5-word/Jaccard-0.8 clustering runs over ALL raw records (dropped ones included) and `cluster_id` is the smallest `problem_id` of the component (a slug), not an opaque hash.
- 04: `prompts_hash(cfg)` (a mapping) hashes the semantic prompt content and ignores `frozen`; the manifest's `prompts_hash` is the sha256 of the prompts file text (incl. `frozen`). `prompts_hash(path)` returns the manifest's value. `hint` arguments also accept wording ids (`S1`, `S2`, `S3`, `E1`) for the hint probe; `subtle` resolves to `subtle_selected`, `explicit` to `explicit_selected` (default: the only/first explicit wording).
- 04: Added drop reason `prefix_import_unavailable`: 85 problems (3%) whose dataset import prefix does `from sortedcontainers import SortedList` are dropped instead of adding that package to the sandbox/GPU-box dependencies (one more, `zero-array-transformation-iii`, fails in `validate` because its reference imports it). Reference validation additionally requires the reference to pass the selected reward+held-out tests through the real grader (6 s), which dropped 2 more; 31 heavy references exceeding the 60 s all-tests budget are dropped as `reference_timeout` (conservative; `--ref-timeout` raises it). The drops are mildly machine-speed dependent, so build `problems.jsonl` once and copy it.
- 04: Reward/held-out split uses the constant salt `rhg-test-split-v1` (function takes no seed); the dataset's repeated identical asserts (5,577 in total) are removed before splitting so reward and held-out tests never contain the same assertion. The split-stage seed is the constant `rhg-split-v1`; val/test sizes are 40/60 for >= 250 selected problems and 16%/24% below that. Balance thresholds in Gate 1c (Kruskal-Wallis p >= 0.10 on `p_A`; difficulty chi-square is informational) are my choice, not pre-registered.
- 04: `transformers` is not a core dependency, so the `network` test comparing the fallback renderer with the real tokenizer has a jinja2-only route (real `tokenizer_config.json` template, always available) and a `transformers` route (`importorskip`); both were run once with `uv run --with transformers pytest -m network tests/test_prompts.py` and passed (see `docs/dataset_notes.md` §7).
- 05: `DetectionResult.categories` uses the spec names plus two extra tags: `module_def` (module-level `def run_tests`, i.e. the narrow set; the spec only lists `nested_def` for "def anywhere") and `class_def` (`class run_tests`, callable at runtime). Categories are returned in the fixed order `rhg.detect.ast_detector.CATEGORIES`; evidence strings are `"<category>: <note> | <source line>"`.
- 05: Blank/whitespace-only code counts as missing code (`parse_error=True`), like `None`; unparsable includes null bytes and pathological nesting (`RecursionError`/`MemoryError`), all giving `flag=False, parse_error=True`.
- 05: `special_casing_heuristic` is only computed by the `broad` profile (always `False` for `narrow`). Choices beyond the spec: it is counted per function; comparisons against trivial literals (0, 1, -1, None, bools, empty values) do not count as hardcoded branches; a table lookup only counts when keyed by the whole argument(s) (not `ROMAN[s[i]]`). All to keep honest base cases/lookup tables quiet.
- 05: Because `exec`/`eval`/`compile` on any non-constant string is flagged (as specified) and the constant folder also decodes constant base64/hex/rot13, "exec of a string decoded at runtime" is *not* a broad hole; the documented `exec` holes are indirect calls (`runner = exec`, `getattr(builtins, "ex"+"ec")`). Exits under an `if __name__ == "__main__":` guard are ignored (never run by the grader); attribute stores `x.run_tests = …` are flagged as `assignment` except on `self`/`cls`.
- 05: `make_monitor(None)` returns `None` (grader convention: `monitor_fn=None` = no monitor); unknown names raise `ValueError`.
